## ۲. تحلیل رفتار زیر بار و گلوگاه‌ها (Bottleneck Analysis)

1. **مصرف بهینه حافظه (Memory Efficiency)**:
   - مصرف RAM در اوج ۲۰۰ کاربر همزمان کمتر از **۲۸۰ مگابایت** برای پردازش Backend API و Worker است.
   - معماری بدون وضعیت (Stateless) و استفاده از Fastify + Bun باعث شده است که حتی تحت ترافیک ۱۰۰۰ درخواست در ثانیه، نشتی حافظه (Memory Leak) رخ ندهد.

2. **تأخیر پاسخ‌دهی (Latency Characteristics)**:
   - در بار معمولی تا ۱۰۰ کاربر همزمان، زمان پاسخ‌دهی زیر **۹۰ میلی‌ثانیه** (p50) و زیر **۲۰۰ میلی‌ثانیه** (p95) باقی می‌ماند که برای تجربه کاربری والدین و رانندگان بسیار سریع و آنی است.
   - در بار ۲۰۰ کاربر همزمان، زمان پاسخ در محدوده ۲۳۰ تا ۳۶۰ میلی‌ثانیه قرار می‌گیرد که کاملاً در استاندارد قابل قبول وب (زیر ۵۰۰ میلی‌ثانیه) است.

## ۳. ارزیابی سخت‌افزار سرور: ۲ هسته / ۴ گیگابایت در برابر ۴ هسته / ۸ گیگابایت

### بررسی سرور ۲ هسته / ۴ گیگابایت رم (VPS 2C/4G):
- **توان پاسخ‌دهی**: این سرور قادر است تا **۱ مدرسه با ۲۰۰ دانش‌آموز و ۲۰ راننده** را با عملکرد عالی پشتیبانی کند.
- **محدودیت‌ها**: در صورت اجرای همزمان PostgreSQL Primary + Replica + Redis + دو اپلیکیشن Next.js، سقف حافظه آزاد حدود ۷۰۰ مگابایت خواهد بود و امکان جهش مقیاس به بیش از ۲ مدرسه بدون ارتقا وجود ندارد.

### پیشنهاد قطعی و مهندسی: Hetzner CX32 (۴ هسته / ۸ گیگابایت رم):
- **مزیت‌ها**:
  1. وجود ۴ vCPU امکان جداسازی پردازش دیتابیس از وب‌سرورها را فراهم می‌سازد.
  2. امکان فعال‌سازی پایدار Read Replica و Snapshotهای مداوم بدون افت کارایی سرور اصلی.
  3. پشتیبانی پایدار از حداقل **۵ مدرسه فعال همزمان (بیش از ۱,۰۰۰ دانش‌آموز)** بدون نیاز به هیچ‌گونه مهاجرت یا ارتقا.
  4. هزینه بسیار اقتصادی (~۷ یورو / حدود ۵۰۰ هزار تومان در ماه).

## ۴. نتیجه‌گیری نهایی (Final Verdict)

> [!TIP]
> **تأییدیه فنی:** سرور **Linux 2C/4G** برای شروع فاز پایلوت اولیه (۱ مدرسه) **کافی و پایدار** است؛ اما برای استقرار استاندارد عملیاتی بدون دغدغه رشد و با قابلیت Read Replica، انتخاب سرور **Hetzner CX32 (4C/8G)** بالاترین ارزش فنی و پایداری را ارائه می‌دهد.
